# Manim Ecosystem: Forks, Ports, Plugins and Related Tools (as of mid-November 2026)

Method note: I pulled star counts, last-push dates and creation dates directly from the GitHub REST API (`api.github.com/repos/...` and `gh search repos`) on 2026-11-14. PyPI versions and dates came from the `pypi.org/pypi/<pkg>/json` API, and download counts from pypistats.org. "Last push" is the date of the last git push to the repo, so it only roughly tracks real development activity. I use "stale" for no push in more than 18 months. The core 3b1b/manim (ManimGL) vs ManimCommunity/manim comparison is out of scope. For context only: 3b1b/manim has 96,489 stars and ManimCommunity/manim has 42,475 stars, latest release v0.22.1 on 2026-10-27 ([GitHub API, 3b1b/manim](https://api.github.com/repos/3b1b/manim); [GitHub API, ManimCommunity/manim releases](https://api.github.com/repos/ManimCommunity/manim/releases/latest)).

## 1. Plugins for ManimCE (and the official plugin registry)

### Takeaway
The official registry at plugins.manim.community lists about 105 PyPI packages. Most are small, single-author projects. A few are mature and actively maintained: manim-slides (presentations, very active), manim-voiceover (TTS and recording, active), manim-physics, manim-chemistry, manim-dsa and manim-fonts. ManimML has the most stars of any plugin (3.5k), but nothing has been pushed since mid-2024 and its last PyPI release was in 2023, so it is effectively stale. Many older plugins (rubikscube, data-structures, code-blocks, chanim, manim-editor) are abandoned or pinned to old Python versions.

### Inferences
- Presentation tooling has consolidated around manim-slides. manim-editor and manim-presentation are dead.
- Plugin health is uneven. Many plugins have repo activity but stale PyPI releases or Python upper bounds (`<3.11`, `<3.13`), which will break on current Python. Pin versions or install from git.
- The registry is filling up with AI-oriented and voiceover-fork packages. This suggests that in 2025–26 the community has been building on voiceover and LLM workflows more than on new domain plugins.

### Gaps
- I did not verify the maintainer attribution "Henrik" for manim-voiceover. The repo is owned by the ManimCommunity org, and I did not open its contributor list.
- I did not check the per-package details for the 100+ registry entries, including manim-claude, manim-mcp, llmanim and manim-studio.
- I found no `manim-code-blocks` repository with significant stars, so the original author repo is unclear.

## 2. IDE tooling, notebooks, playgrounds, mobile

### Takeaway
VS Code has two real options. Manim Sideview targets ManimCE (about 129k installs, maintained). Manim Notebook targets ManimGL interactive previewing (about 2.5k installs, active, v1.0.x). Jupyter support is built into ManimCE through the `%%manim` cell magic and Binder (try.manim.community). Browser editors are a growing category. I found no serious mobile apps.

### Cited Findings
- **Manim Sideview** (Rickaym). VS Code extension for ManimCE with live preview of video and image output, a Mobject gallery of snippets, scene auto-detection, render-on-save and venv detection. 129,172 installs, 5 stars from 8 reviews, version 0.4.3 per its listing. The repo has 187 stars and was pushed 2026-09-09 — [VS Code Marketplace](https://marketplace.visualstudio.com/items?itemName=Rickaym.manim-sideview); [GitHub API](https://api.github.com/repos/Rickaym/Manim-Sideview)
- **Manim Notebook** (publisher "Manim Notebook Contributors", repo Manim-Notebook/manim-notebook; originated by Splines). Interactive previewing for **ManimGL** in VS Code: you split a file into `##` "Manim Cells", preview a selection, and export video, using ManimGL's interactive/checkpoint mode. 2,485 installs, version about 1.0.1. The repo (TypeScript) has 49 stars, was created 2024-10-14 and pushed 2026-08-05 — [VS Code Marketplace](https://marketplace.visualstudio.com/items?itemName=Manim-Notebook.manim-notebook); [GitHub API](https://api.github.com/repos/Manim-Notebook/manim-notebook)
- **Jupyter**: ManimCE ships a built-in `%%manim` magic. The official interactive tutorial is at https://try.manim.community/ (Binder-based; source in ManimCommunity/jupyter_examples, 26 stars, pushed 2026-11-03). Colab works too, but you must reinstall each session. A Docker image `manimcommunity/manim` can run JupyterLab — [Manim docs: Jupyter](https://docs.manim.community/en/stable/installation/jupyter.html); [GitHub API](https://api.github.com/repos/ManimCommunity/jupyter_examples)
- **jupyter-manim** (krassowski). An older third-party `%%manim` magic from 2019. 198 stars, pushed 2026-04-13. Largely superseded by the built-in magic — [GitHub API](https://api.github.com/repos/krassowski/jupyter-manim)
- **manim-widget** (rambip). "Manim in your notebooks, truly interactive." 10 stars, pushed 2026-11-09. A new project, also listed in the plugin registry — [GitHub API](https://api.github.com/repos/rambip/manim-widget); [plugins.json](https://plugins.manim.community/plugins.json)
- **Manim Binder** (naveen521kk). Adds interactive, runnable code blocks to the Manim docs through the Binder API — [naveen521kk.pages.dev](https://naveen521kk.pages.dev/project/manim-binder)
- GUI "studios": **manim-studio** (MathItYT; 93 stars; last push 2024-03; stale), **manimate** (kevcen; 140 stars; "An animation studio for Manim"; last push 2024-07; stale), **eulerv2** (eulertour; web front end to manim; 104 stars; stale 2022), **Manim-Motion** (BlommeJan; browser-based visual editor; 45 stars; 2026-04), **Manimble** (pachterlab; edits manim slides; 7 stars; pushed 2026-11-13), plus many 0–3-star "manim-editor" attempts in 2026 — [gh search](https://github.com/search?q=manim+editor&type=repositories&s=stars)
- **PyCharm**: npetrangelo/manim-plugin, 1 star, from 2021. Effectively nothing exists for PyCharm — [gh search](https://github.com/search?q=manim+android&type=repositories)
- **DiscordManimator** (ManimCommunity). A Discord bot that renders Manim snippets. 58 stars, pushed 2026-01 — [gh search](https://github.com/ManimCommunity/DiscordManimator)
- **Mobile**: the only hit is "m4a – Manim Android APK Builder" (programmersd21; 5 stars; 2026-06). I found no maintained iOS or Android Manim app — [gh search](https://github.com/search?q=manim+android&type=repositories)

### Inferences
- For a ManimCE workflow, Sideview plus the `%%manim` magic is the standard setup. For ManimGL, Manim Notebook gives a 3b1b-style interactive workflow.
- The closed-source studio.academa.ai (see Section 3) and the TS manim-web are the most capable browser options now. The old ManimCommunity web presenter efforts are dead.

### Gaps
- I could not confirm that try.manim.community is currently online.
- I did not get the last-updated date for Sideview from the Marketplace page, which showed inconsistent changelog versions.
- I found no evidence of a "Manim web" official playground beyond Binder.

## 3. Forks and ports (other languages, reimplementations, Chinese community forks)

### Takeaway
The most important new development is **ManimGX** (Academa, October 2026). It is a ManimCE-API-compatible engine with a Rust/wgpu core that reached about 2.7k stars in roughly five weeks and claims a ~90× speedup over ManimCE. Its closed-source sibling studio.academa.ai runs the same engine in the browser through WebGPU. Other live reimplementations: **JAnim** (Python, real-time preview, v5), **ranim** (Rust, inspired by Manim and JAnim), **manim-web** (TypeScript/Three.js port, actively developed) and **Manim.js** (p5.js). Julia, Swift and Go "ports" are essentially nonexistent. The Chinese manim-kindergarten and Cigar666 repositories, once central, have been dormant since 2022.

### Cited Findings
- **ManimGX** (academa-labs/manimgx; Academa, by Abdullah Geduk and Sina Atalay). "The animation engine for agents". You write scenes in Python with the Manim CE API, on a Rust GPU core (wgpu). Requires Python 3.13+. Features: browser support through Pyodide and WebGPU, 2D/3D, LaTeX or Typst math without a LaTeX install, `manimgx inspect` for layout checks aimed at agent feedback, `self.say()` speech sync, and an llms.txt. MIT for its own code; native wheels bundle x264 and are GPL-3.0+. The maintainers' own benchmark: 36.2 s of 1080p60 video rendered in 3.08 s on an M4 Pro, "90.6× faster than ManimCE" (self-reported, single machine). Repo created 2026-10-05, 2,736 stars, pushed 2026-11-09, PyPI 0.1.1 released 2026-10-07 — [GitHub README](https://github.com/academa-labs/manimgx); [GitHub API](https://api.github.com/repos/academa-labs/manimgx); [PyPI](https://pypi.org/pypi/manimgx/json)
- **studio.academa.ai** (Show HN: "Manim (3Blue1Brown's animation engine) in the browser via WebGPU", 49 points). Monaco editor, live preview and an AI agent. The core is Rust exposed through PyO3, compiled to WASM in Pyodide and rendered with wgpu/WebGPU. HN commenters criticized the branding as misleading, the code as closed source, the paywalled examples and possible AI-ported code, and reported Safari and Windows-on-ARM failures. The team said the engine was built independently over about 2 months and that only the AI features are paid — [HN thread](https://hn.svelte.dev/item/49091703)
- **JAnim** (jkjkil4/JAnim). A Python engine inspired by manim, focused on "real-time feedback": live code refresh and a scrubbable preview. Python 3.12+, `pip install janim`, latest version 5.0.3, more than 2,200 commits, docs at janim.readthedocs.io in English and Chinese. 290 stars, pushed 2026-11-11. Very active. (It is Python, not Java.) — [GitHub](https://github.com/jkjkil4/JAnim); [GitHub API](https://api.github.com/repos/jkjkil4/JAnim); [PyPI](https://pypi.org/pypi/janim/json)

"An animation engine implemented in rust, inspired by manim and JAnim", built on wgpu. 664 stars, pushed 2026-11-09, crate at 0.2.x — [GitHub API](https://api.github.com/repos/AzurIce/ranim); [lib.rs](https://lib.rs/crates/ranim); [docs.rs](https://docs.rs/crate/ranim/0.2.1/source/README.md)

### Inferences
- Performance is the main motivation behind the forks: GPU, Rust and real-time preview (ManimGX, ranim, JAnim, noon). ManimGX is notable because it keeps the ManimCE API, so existing code and LLM knowledge of ManimCE carry over. It is very new (v0.1.x) and its benchmarks are self-reported, so treat it as promising but unproven.
- For browser and interactive use, maloyan/manim-web is the most credible open-source option. Manim.js uses p5.js and is not API-compatible.

### Gaps
- I found no evidence of projects named "manim-ce-gl", "ManimGo", a Swift port, or a "ManimCairo-based fork" as distinct notable projects. Older forks of ManimCairo (the pre-2021 3b1b Cairo branch) exist, but I identified none with meaningful activity.

## 4. AI tools that generate Manim (LLM pipelines, agents, MCP servers, skills, research)

### Takeaway
Text-to-Manim is now the busiest growth area of the ecosystem. Several open-source pipelines have thousands of stars: Math-To-Manim (2.9k), ManimGX (2.7k, agent-oriented engine), Code2Video (2.4k, ICML 2026), TheoremExplainAgent (1.5k, ACL 2025 oral) and manim_skill (1.3k Claude/agent skill). There are also a dozen MCP servers and a steady stream of 2026 arXiv papers on render-feedback agents and RL fine-tuning. The research consistently finds that code that executes is not the same as a good-looking video: layout overlap and overflow remain the core failure.

### Cited Findings
**Generators / agent pipelines**
- **Generative Manim** (marcelo-earth). Apache-2.0 text-to-Manim suite with a web demo (generative-manim.vercel.app), an "Animation Processing Interface" API, a benchmark with render-based pass@k, and an SFT/DPO/GRPO training pipeline that uses the Manim renderer as verifier. The README lists OpenAI, Anthropic (Claude), Google Gemini and Moonshot Kimi models plus open-weight fine-tunes (in progress). ### Inferences
- Agent-oriented tooling is reshaping the ecosystem. Engines now ship llms.txt files, inspection commands and skills (ManimGX, manim_skill), and MCP servers are common. Most agent tools target ManimCE because LLMs know its API best; a notable minority (manimgl-mcp, manim-mcp-ai) target ManimGL.
- Many MCP servers and research repos go stale quickly after publication: abhiemj's server has had no push since May 2025, TheoremExplainAgent since July 2025 and Manimator since February 2025. Prefer actively maintained pipelines such as Math-To-Manim, Generative Manim and ManimCat.

### Gaps
- The model names in the Generative Manim and Math-To-Manim READMEs (e.g. "GPT-6 Astra", "claude-fable-5-2") are reported as written in those READMEs. I did not verify them independently.
- I did not open the arXiv PDFs, so the details are from abstracts and snippets.
- I have no star counts for manimgl-mcp, mcp-manimgl or manim-mcp-ai.

## 5. Learning resources (tutorials, courses, curated lists)

### Takeaway
The official ManimCE docs and tutorials, try.manim.community, Behackl's "manim-with-ease" and the community awesome-manim list are the maintained resources. The once-dominant Theorem of Beethoven course and the Chinese tutorial repos target the old 3b1b API and have been frozen since 2020–2022.

### Cited Findings
- **awesome-manim** (ManimCommunity). A curated database of Manim creators and channels, shown on manim.community/awesome. 549 stars, pushed 2026-10-07. It is a list of creators, not of tools — [GitHub API](https://api.github.com/repos/ManimCommunity/awesome-manim); [ecosyste.ms](https://awesome.ecosyste.ms/projects/github.com%2FManimCommunity%2Fawesome-manim)

AnimacionesConManim (Spanish) has 44 stars (2019). Stale; written for old 3b1b manim — [GitHub API](https://api.github.com/repos/Elteoremadebeethoven/AnimationsWithManim); [GitHub API](https://api.github.com/repos/Elteoremadebeethoven/MyAnimations)

### Inferences
- New learners on ManimCE should start with the official docs and quickstart, try.manim.community, and Sideview. Older YouTube and GitHub courses (Theorem of Beethoven, 2019–2021 tutorials) use pre-split APIs and will mislead.
- Agent skills (manim_skill and similar) are emerging as a de facto "learning resource" for LLM-assisted users.
