# Start with Community Manim, borrow Grant's tricks

Anyone starting with Manim in late 2026 should install **Manim Community Edition (ManimCE, PyPI `manim`)**, not the 3Blue1Brown version, and every official source agrees, Grant Sanderson included. He tells newcomers they "should probably start with this Community Edition" ([3Blue1Brown FAQ](https://www.3blue1brown.com/faq)). Manim began in early 2015 as Grant's personal Python library. Volunteers forked it into ManimCE in mid-2020, and in early 2021 Grant's own OpenGL rewrite became "ManimGL" (`manimgl`). The two editions share a lineage but cannot run each other's code. ManimCE is the documented, tested, regularly released edition: v0.22.1 shipped on 27 October 2026 and the repo has about 42.5k stars. ManimGL is the experimental tool 3Blue1Brown actually uses. It has about 96.5k stars, an interactive live-preview workflow, and no PyPI release since December 2024. Around these two cores sits a busy ecosystem: about 105 registered plugins, Rust, TypeScript and browser reimplementations, and, the fastest-growing part, AI pipelines that turn prompts into Manim code. Beyond Manim, Motion Canvas is the main code-based rival and After Effects the main GUI one. Most creators combine a code tool for precise math with an ordinary video editor. For a Windows beginner, the practical setup is ManimCE installed with `uv`, the Manim Sideview extension for VS Code, and LaTeX or Typst added only once you need equations.

## One codebase split into three Manims between 2015 and 2021

Manim started as a personal programming project. Grant wrote a Python graphics library to practise coding, and his first 3Blue1Brown video went up on 4 March 2015 ([Wikipedia](https://en.wikipedia.org/wiki/Manim)). He still calls it "a custom Python library... very bespoke" ([Ben Sparks demo transcript](https://rosetta.to/u/3blue1brown/how-i-animate-3blue1brown-a-manim-demo-with-ben-sparks)), and his FAQ describes his version as "a testing ground for new ideas while making videos" ([3Blue1Brown FAQ](https://www.3blue1brown.com/faq)). Because it was built for one user, it was hard for anyone else to install. That pushed outside developers to **fork it into the Community Edition in mid-2020**, aiming for stability, tests and friendlier onboarding. Meanwhile Grant had been building faster OpenGL rendering on a `shaders` branch since late 2019, and **in early 2021 he merged it into master as ManimGL**. The older pre-OpenGL code survives as the `cairo-backend` branch ([ManimCE FAQ](https://docs.manim.community/en/stable/faq/installation.html); [3b1b/manim README](https://github.com/3b1b/manim)).

That history produced three packages that are easy to mix up. The import line in any script tells you which one it was written for:

| Edition | PyPI name | Import line | Docs | Use it for |
|---|---|---|---|---|
| Manim Community (ManimCE) | `manim` | `from manim import *` | docs.manim.community | Learning, tutorials, plugins, AI tools |
| ManimGL (Grant's) | `manimgl` | `from manimlib import *` | 3b1b.github.io/manim | Matching 3b1b code and its interactive workflow |
| ManimCairo (legacy) | `manimlib` | `from manimlib.imports import *` | none maintained | Rendering 3b1b projects from 2019 and earlier |

Sources: [ManimCE FAQ](https://docs.manim.community/en/stable/faq/installation.html); [3b1b/manim README](https://github.com/3b1b/manim).

The ManimGL README states that the package is `manimgl`, "not `manim` or `manimlib`", and warns that following the install instructions of both editions in the same environment causes breakage ([GitHub](https://github.com/3b1b/manim)). Community advice is to keep each edition in its own virtual environment ([r/manim thread](https://reddit.birdcat.cafe/r/manim/comments/1jmhb7a/is_it_possible_to_have_manim_community_and)). This is the most common beginner trap. Most old YouTube tutorials, including the once-dominant Theorem of Beethoven course (1,237 stars, no push since 2021), target the old 3b1b API and **will mislead a ManimCE learner** ([GitHub API](https://api.github.com/repos/Elteoremadebeethoven/AnimationsWithManim)).

## ManimGL wins on live iteration, ManimCE on everything else

The two editions differ in what they are for. **ManimGL renders in real time with OpenGL.** Calling `self.embed()` drops you into an IPython shell beside a live window, where you can pan, zoom and rotate the 3D view with the keyboard and mouse ([ManimGL quickstart](https://3b1b.github.io/manim/getting_started/quickstart.html)). Its central workflow is `manimgl file.py Scene -se <line>`, which starts the scene and stops at a given line, followed by `checkpoint_paste()`, which re-runs whatever code is on the clipboard. That code can be replayed from a saved state, skipped without animation, or recorded to file ([3b1b/videos README](https://github.com/3b1b/videos)). The cost is that ManimGL is officially "more experimental", and its breaking changes go undocumented ([ManimCE FAQ](https://docs.manim.community/en/stable/faq/installation.html)). The latest PyPI release, 1.7.2, dates from 13 December 2024, about 2.5 years after 1.6.1 ([PyPI](https://pypi.org/project/manimgl/#history)). Grant's own videos repo tells users to install from source because "the latest published release is out of date" ([3b1b/videos](https://github.com/3b1b/videos)). Master is still active: VideoMobject and Sprite support landed on 9 September 2026 ([commits](https://github.com/3b1b/manim/commits/master)).

**ManimCE trades that interactivity for stability.** It renders with Cairo by default (an OpenGL renderer also exists), and it has tests, documentation, semantic versioning and a plugin system ([ManimCE FAQ](https://docs.manim.community/en/stable/faq/installation.html)). It is also moving fast. Since v0.19.0 (January 2025) it writes video through PyAV rather than an external ffmpeg process. v0.19.2 raised the minimum Python to 3.11 and added 3.14 support. v0.20.0 rewrote `MathTex`. **v0.21.0 (August 2026) added Typst as a LaTeX-free option for math**, and v0.22.0 (October 2026) added a `Manager` rendering class and a unified `format` option ([releases](https://github.com/ManimCommunity/manim/releases)). A larger "experimental" rewrite aims to make mobjects renderer-independent and, according to an unofficial migration guide, to make OpenGL the default ([migration guide](https://jasongrace2282.github.io/manim-experimental-migration)). As of November 2026 there is no ManimCE 1.0 and no public date for one. A community developer described "no concrete timeline" in January 2025 ([r/manim](https://lr.us.psf.lt/r/manim/comments/1i5s5eb/manim_community_v0190_has_been_released/m8c1c9t/?context=3)), so treat the experimental branch as unreleased.

The star counts (96.5k for ManimGL against 42.5k for ManimCE) reflect the 3Blue1Brown brand and the repo's age, not who uses which edition ([3b1b/manim](https://github.com/3b1b/manim); [ManimCommunity/manim](https://github.com/ManimCommunity/manim)). ManimCE is the project with governance: an elected Steering Council, OpenCollective funding, a Discord, and the r/manim subreddit. The funding details come from a roadmap last edited in 2022, so they may be out of date ([Roadmap wiki](https://github.com/ManimCommunity/manim/wiki/Roadmap)). ManimGL is simply Grant's project.

## 3Blue1Brown runs ManimGL from Sublime Text, and now with Claude Code

Grant's actual pipeline is unusually well documented. He runs **ManimGL installed from source**, driven from **Sublime Text** through the Terminus package and custom commands that send highlighted code to the running shell. Keybindings such as `super+r` run `manim_checkpoint_paste`, and the recorded and skipped variants have their own keys ([3b1b/videos README](https://github.com/3b1b/videos)). His October 2024 demo with Ben Sparks walks through the setup ([3B1B lesson](https://www.3blue1brown.com/lessons/manim-demo/)). Manim produces only the clips. Grant says it "is just a tool for making individual clips to be edited together later" and advises using conventional editing software "for as much as you can" ([FAQ](https://www.3blue1brown.com/faq)). He has never publicly named which editor he uses, so claims that it is Premiere or Final Cut are unsourced. Vincent Rubinetti writes most of the music.

Two details have changed by 2026. First, **3Blue1Brown is now a small studio**: the FAQ lists Paul Dancstep, Aaron Gostein, Nishad Deulkar, Mitchell Zemil and Claire Vermillion in animation or illustration roles ([FAQ](https://www.3blue1brown.com/faq)). Their tools are undocumented, and some recent visuals were probably made outside Manim. Second, the videos repo now ships a **`CLAUDE.md` for AI-assisted coding**. It tells the model that "This repository uses the 3b1b version of Manim, not ManimCommunity", to use `Tex()` rather than `MathTex()`, and to lay scenes out with `.arrange()`/`.next_to()` instead of hand-computed coordinates. It also shows a 4K/30fps render config and Dropbox-hosted assets ([CLAUDE.md](https://raw.githubusercontent.com/3b1b/videos/master/CLAUDE.md)). The repo, with about 11.5k stars, is the best real-world reference for ManimGL code ([GitHub API](https://api.github.com/repos/3b1b/videos)).

Other creators split along clear lines. **ManimGL** is used by Welch Labs, which hires freelance Manim animators who "submit animations as pull requests" ([Welch Labs](http://www.welchlabs.com/freelance-manim-animator)) and also uses Illustrator, After Effects and Premiere ([editor role](http://www.welchlabs.com/editor)). **Reducible** moved from old 3b1b manim to ManimCE ([repo](https://github.com/nipunramk/Reducible)), and Vcubingx publishes his Manim source ([repo](https://github.com/vivek3141/videos)). **Motion Canvas** was built by aarthificial for his own channel. Polylog's Tomáš Sláma switched to it in October 2024, citing "severe MBS (Manim Burnout Syndrome)" and wanting live preview ([slama.dev](https://slama.dev/motion-canvas/1/)). **Unity** is behind Freya Holmér's Bézier video, a Summer of Math Exposition 1 winner, made with her Shapes library ([acegikmo.com](https://acegikmo.com/shapes)). Primer moved from a Blender-Python library, itself structured after Manim, to Unity ([primerpython](https://github.com/Helpsypoo/primerpython)). **Adobe** is the tool at the illustrated end: Kurzgesagt draws in Illustrator and animates in After Effects, with some Cinema 4D, at up to about 1,200 hours per video ([transcript](https://rosetta.to/u/kurzgesagt/how-to-make-a-kurzgesagt-video-in-1200-hours); [Gigazine](https://www.gigazine.net/gsc_news/en/20200217-science-animation-making/)). Artem Kirsanov mixes After Effects, Python and Blender ([Class Central](https://www.classcentral.com/course/youtube-how-i-make-science-animations-205178)). No source names the tools behind Veritasium, Numberphile, Mathologer, TED-Ed or most other channels, and **no survey of tool use among Summer of Math Exposition entrants exists** ([SoME1 results](https://www.3blue1brown.com/blog/some1-results)), so claims about those channels are guesswork.

## About 105 plugins, a Rust wave and an AI gold rush

**Plugins.** The official registry at plugins.manim.community lists about 105 packages ([plugins.json](https://plugins.manim.community/plugins.json)), but only a handful are both healthy and useful:

| Plugin | What it does | Status (Nov 2026) |
|---|---|---|
| manim-slides | Turns scenes into presentations: reveal.js, PowerPoint, Qt presenter | v5.7.0 (Sept 2026), very active, works with both editions |
| manim-voiceover | TTS or microphone narration synced to animation | v0.4.0 (June 2026), most downloaded (~7.9k/month) |
| manim-physics | Rigid bodies, electromagnetism, waves, optics | Repo active; PyPI stuck at 2024, Python < 3.13 |
| manim-chemistry | Molecules, periodic table, orbitals | v0.5.1 (2025) |
| manim-dsa | Arrays, stacks, graphs, algorithms | v0.4.0 (2025), active |
| ManimML | Neural-network visuals | 3.5k stars but stale since 2023–24 |

Sources: [manim-slides](https://api.github.com/repos/jeertmans/manim-slides); [manim-voiceover](https://pypistats.org/api/packages/manim-voiceover/recent); [manim-physics](https://pypi.org/pypi/manim-physics/json); [manim-chemistry](https://pypi.org/pypi/manim-chemistry/json); [manim-dsa](https://pypi.org/pypi/manim-dsa/json); [ManimML](https://api.github.com/repos/helblazer811/ManimML).

**Plugin health is the main risk.** Several packages have upper bounds on Python (`<3.11`, `<3.13`) that will not install on the Python 3.11+ that ManimCE now requires. manim-editor and manim-presentation have been abandoned in favour of manim-slides, and manim-data-structures in favour of manim-dsa ([registry analysis](https://plugins.manim.community/plugins.json)). The most-starred application built on Manim is not a plugin at all: git-sim, a visual Git simulator with about 4.7k stars ([GitHub](https://github.com/initialcommit-com/git-sim)). For editors, **Manim Sideview** (about 129k installs) gives ManimCE live preview in VS Code ([Marketplace](https://marketplace.visualstudio.com/items?itemName=Rickaym.manim-sideview)), **Manim Notebook** brings Grant's cell-by-cell workflow to VS Code for ManimGL users ([Marketplace](https://marketplace.visualstudio.com/items?itemName=Manim-Notebook.manim-notebook)), and ManimCE has a built-in Jupyter `%%manim` magic ([docs](https://docs.manim.community/en/stable/installation/jupyter.html)). No real PyCharm or mobile tooling exists.

**Forks and ports.** Most new engines are chasing speed and live preview. The standout is **ManimGX** (Academa, October 2026), which keeps the ManimCE Python API on a Rust/wgpu GPU core, renders math with no LaTeX install, and markets itself as "the animation engine for agents". It reached about 2.7k stars in five weeks and claims a 90.6× speedup over ManimCE. That figure is the maintainers' own benchmark on one M4 Pro machine. The package is v0.1.1, needs Python 3.13+, and its native wheels bundle GPL-3.0 x264 ([README](https://github.com/academa-labs/manimgx); [PyPI](https://pypi.org/pypi/manimgx/json)). Its closed-source browser sibling, studio.academa.ai, drew Hacker News criticism for branding itself "Manim" and for paywalled features ([HN](https://hn.svelte.dev/item/49091703)). Other live projects include **JAnim** (Python, real-time scrubbable preview, v5, bilingual docs) ([GitHub](https://github.com/jkjkil4/JAnim)), **ranim** (Rust, 664 stars, unstable 0.2.x API) ([lib.rs](https://lib.rs/crates/ranim)), **manim-web** (a TypeScript/Three.js port with a Python-to-TS converter, 515 stars) ([GitHub](https://api.github.com/repos/maloyan/manim-web)) and **Manim.js** (p5.js, not API-compatible) ([GitHub](https://api.github.com/repos/JazonJiao/Manim.js)). There are no meaningful ports to Julia, Swift or Go; Julia users have the stale Javis.jl instead ([GitHub API](https://api.github.com/repos/JuliaAnimators/Javis.jl)). The Chinese community repos that mattered in 2020–22, manim-kindergarten and cigar666, are now dormant ([GitHub API](https://api.github.com/repos/manim-kindergarten/manim_sandbox)). JAnim and ranim come from Chinese developers, so the newer wave of engines also has roots there.

**AI and LLM tools are now the fastest-growing part of the ecosystem.** Manim has quietly become the default output language for "explain this math as a video" systems. Open-source pipelines include Math-To-Manim (about 2.9k stars, a staged agent chain with repair loops and an MCP mode) ([GitHub](https://github.com/HarleyCoops/Math-To-Manim)), Code2Video (about 2.4k, ICML 2026) ([GitHub API](https://api.github.com/repos/showlab/Code2Video)), TheoremExplainAgent (about 1.5k, ACL 2025, dormant since July 2025) ([GitHub API](https://api.github.com/repos/TIGER-AI-Lab/TheoremExplainAgent)), Generative Manim (943, with a benchmark and RL training loop) ([GitHub](https://github.com/marcelo-earth/generative-manim)) and ManimCat (502) ([GitHub API](https://api.github.com/repos/Wing900/ManimCat)). For coding agents there are skills such as **manim_skill (about 1.3k stars)** ([GitHub API](https://api.github.com/repos/adithya-s-k/manim_skill)), a dozen MCP servers (the most-starred, abhiemj/manim-mcp-server, has been stale since May 2025) ([GitHub API](https://api.github.com/repos/abhiemj/manim-mcp-server)), and registry plugins such as manim-claude and manim-mcp. The 2026 research all reaches the same conclusion. OmniManim notes that "executable correctness does not imply render quality" ([arXiv 2605.15585](https://arxiv.org/pdf/2605.15585)), and PhysicsSolutionAgent reports ongoing trouble generating reliable Manim code ([arXiv 2601.13453](https://arxiv.org/pdf/2601.13453)). **Overlapping objects and content running off-frame remain the typical failures**, which is why newer tools add visual review loops and why Grant's `CLAUDE.md` insists on relative layout.

## Motion Canvas is the code rival, After Effects the GUI default

Among code-first tools, **Motion Canvas** (TypeScript) is Manim's closest peer: generator-function scenes, a browser editor with a timeline and hot reload, MIT licence and about 19.8k stars ([GitHub](https://github.com/motion-canvas/motion-canvas)). Its upstream maintenance is disputed. The last release found is 3.17.2 (December 2024), and v4 never shipped ([Yarn](https://classic.yarnpkg.com/en/package/@motion-canvas/ui)). Critics call it abandoned, while defenders call it "stable" with 2,800+ Discord members ([HN](https://hn.svelte.dev/item/47155375)). The maintainer said in 2024 that he wrote "99% of Motion Canvas", a single-maintainer risk ([discussion #1015](https://github.com/orgs/motion-canvas/discussions/1015)). The **Canvas Commons** fork is the actively maintained continuation, with the same API and different imports ([slama.dev](https://slama.dev/motion-canvas/2/)). **Revideo** is a Motion Canvas fork built for templated, server-side rendering. It now powers the commercial AI editor Midrender, and its open-source repo reportedly lags behind ([YC](https://www.ycombinator.com/companies/midrender); [Webfolio](https://www.webfolio.to/tools/revideo)). **Remotion** (React, rendered in headless Chromium) is the most widely used code-to-video tool, at about 60k weekly npm downloads. It is free only for individuals and organisations of up to three people ([license](https://remotion.dev/license); [PkgPulse](https://www.pkgpulse.com/guides/remotion-vs-motion-canvas-vs-revideo-programmatic-video-2026)). The older academic alternatives are fading: Reanimate (Haskell) last released in 2022 ([Hackage](https://hackage-origin.haskell.org/package/reanimate)) and Javis.jl last pushed in 2024. **Penrose** fills a different niche, producing optimised static diagrams from mathematical notation ([Penrose 3.0](https://penrose.cs.cmu.edu/blog/v3)). For slides, **Touying** in Typst animates equations step by step but cannot export video ([Typst Universe](https://typst.app/universe/package/touying)).

Manim keeps a real edge on one point: **glyph-level equation morphing**. Only Manim automatically matches LaTeX glyphs between two equations. GUI tools bolt LaTeX on afterwards. After Effects users import LaTeX-rendered PDFs as vectors or buy the Windows-only AnyTex plugin ([Adobe Community](https://community.adobe.com/t5/after-effects-discussions/type-math-equations-in-after-effects/td-p/10816932); [aescripts](https://aescripts.com/authors/streamline/)). Blender gets LaTeX through the free LaTeX Text Generator extension (v1.1.0, May 2026) ([Blender Extensions](https://extensions.blender.org/add-ons/latex-text-generator/)). Keynote takes LaTeX directly, but each equation becomes a static image, and its Magic Move, like PowerPoint's Morph, interpolates whole objects rather than glyphs ([Apple Support](https://support.apple.com/it-ch/guide/keynote/tan72a69d01f/14.0/mac/1.0); [Microsoft](https://support.microsoft.com/en-us/PowerPoint/training/use-the-morph-transition-in-powerpoint)). GeoGebra exports slider animations as GIFs, while Desmos exports only still images, so screen recording is the practical route ([GeoGebra](https://www.geogebra.org/m/zkx7cc4p); [Aperiodical](https://aperiodical.com/2015/07/gifsmos/)). Grant himself points GUI-minded users to Desmos and GeoGebra ([FAQ](https://www.3blue1brown.com/faq)).

| Need | Best fit | Cost |
|---|---|---|
| Equation derivations, graphs, proofs | ManimCE (or ManimGL) | Free, MIT |
| Code-first with timeline/live preview, web devs | Motion Canvas / Canvas Commons | Free, MIT |
| Data-driven or templated video at scale | Remotion, Revideo | Remotion paid above 3 staff |
| Illustrated science storytelling | Illustrator + After Effects | AE ~US$22.99/mo |
| Free 3D with math | Blender 5.x + LaTeX add-on | Free, GPL |
| Procedural 2D motion design (GUI) | Cavalry | Free Starter, Pro ~$20/mo |
| Teachers with no budget | Keynote Magic Move, PowerPoint Morph, GeoGebra | Free or bundled |
| Quick narrated document summaries | NotebookLM Video Overviews | Free with caps |

Sources: [Toolradar Cavalry](https://toolradar.com/tools/cavalry/pricing); [design-offset AE](https://design-offset.com/adobe-after-effects-pricing); [Blender 5.0 notes](https://developer.blender.org/docs/release_notes/5.0/grease_pencil/); [Google blog](https://blog.google/technology/google-labs/video-overviews-nano-banana/). Third-party aggregators disagree on prices, so check vendor pages before buying. Generative video models and NotebookLM cannot guarantee correct geometry or text, so do not rely on them for exact mathematics.

## A practical starting path for "Manim Test" on Windows

**Pick ManimCE.** It has the documentation, the plugins, the active releases and nearly all of the AI tooling, and Grant himself tells beginners to use it ([FAQ](https://www.3blue1brown.com/faq)). The officially recommended installer is **`uv`**. From inside `D:\Projects\AI Code Projects\Manim Test`, run `uv python install`, then `uv init` (or `uv init manimations` for a subfolder), then `uv add manim`, then `uv run manim checkhealth` to verify the installation ([ManimCE uv docs](https://docs.manim.community/en/stable/installation/uv.html)). Two Windows-specific snags appear in the docs. If you see a "Microsoft Visual C++" error, install the C++ Build Tools ("Desktop development with C++"). **LaTeX is optional**: install MiKTeX only when you need `MathTex`, or skip it entirely with `uv add "manim[typst]"`, which bundles Typst for math. Because ManimCE writes video through PyAV, the uv install page does not list a separate FFmpeg install ([releases](https://github.com/ManimCommunity/manim/releases)). ManimGL still needs FFmpeg and MiKTeX ([README](https://github.com/3b1b/manim)). Remember that ManimCE now requires **Python 3.11 or later**, which `uv` handles for you.

For a workflow, install **Manim Sideview** in VS Code for render-on-save preview ([Marketplace](https://marketplace.visualstudio.com/items?itemName=Rickaym.manim-sideview)), and render a first scene with `uv run manim -pql scene.py MyScene` (low quality, opens the result when done). Learn from the official ManimCE tutorials and try.manim.community, and **ignore pre-2021 tutorials and anything that imports `manimlib`** ([GitHub API](https://api.github.com/repos/ManimCommunity/jupyter_examples)). If you use an AI coding assistant, a Manim skill such as manim_skill, plus project instructions modelled on Grant's `CLAUDE.md` (relative layout, a stated edition, no hard-coded coordinates), addresses the overlap and off-frame failures that the research keeps finding ([CLAUDE.md](https://raw.githubusercontent.com/3b1b/videos/master/CLAUDE.md)). Have the assistant render each scene and check the output frames, not just confirm that the code runs. Add manim-voiceover for narration and manim-slides for talks when you need them, and pin plugin versions. Edit the clips in an ordinary editor rather than syncing audio inside Manim, as Grant advises. Install ManimGL later, in a **separate virtual environment**, if you want to study the 3b1b/videos source or try the `-se`/`checkpoint_paste()` workflow. ManimGX is worth testing once it matures past v0.1, but do not start there yet.

## Conclusion

The edition split now matters less than whether a tool exposes the ManimCE API. That API has become a de facto standard well beyond its own codebase: ManimGX reimplements it in Rust, manim-web converts it to TypeScript, and most LLM pipelines generate it because models know it best. That gives ManimCE a lasting advantage that does not depend on its renderer. Even if a GPU engine eventually replaces Cairo, code written today against `from manim import *` will probably carry over. The weak point is not rendering speed but layout judgment. Agents can produce Manim code that runs and still looks wrong, and 3Blue1Brown's answer, project instructions plus human iteration in a live preview, is the pattern worth copying.

The creator evidence also corrects a common assumption: almost no serious channel works entirely in Manim. Grant edits in a conventional editor and now employs illustrators, Welch Labs pairs ManimGL with Adobe tools, and Kurzgesagt, Primer and Freya Holmér made their signature work without Manim at all. Manim is best treated as a precision instrument for equations, graphs and geometric transformations inside a larger editing pipeline, not as a complete video studio. Starting with that expectation saves a beginner from the "Manim Burnout" that sent at least one well-known creator to Motion Canvas.
